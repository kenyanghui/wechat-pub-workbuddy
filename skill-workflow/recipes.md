# 实战经验与踩坑记录（按主题速查）

## 编排模式

- **主控+子代理**：主控会话只做编排（读配置→建目录→spawn→验证→归档），重活交给子代理。topic/writer/qa/format 四类子代理可按篇并行。
- **质检验稿分离**：写和检用不同子代理（writer/qa 分开），qa 用规则引擎评分（七维打分+一票否决项），<85 打回重写，同篇最多 2 次——防止无限循环烧 token。
- **进化台账（RSI ledger）**：每轮运行结束回写避重记录（素材 7 天内不重复）、风格偏好、金句库。这是技能"越用越聪明"的关键，没有台账的多轮技能会反复犯同样的错。
- **产物目录约定**：`<项目根>/pipeline/<日期>/p1|p2|p3/`，每步产物编号命名（01_topics → 02_drafts → 03_qa → 04_queue），断点续跑靠文件名即可判断进度。

## 外部 API 集成

- **先实测再写文档**：IMA 的 `move_knowledge` 是静默 no-op 桩（参数全对也无任何效果），36 种组合实测才发现；`delete/update_knowledge` 端点根本不存在。这类结论存进 `references/*-mechanics.md`，标注"实测"。
- **代理干扰**：本机代理会导致 API 403/无响应，脚本内直接绕过代理直连。
- **IP 白名单类错误（40164）**：公众号 token 请求报 40164 = 本机出口 IP 不在白名单，diagnose.py 直接打印该加白的 IP，用户复制粘贴即可。
- **下载/上传绕道**：Gitea 附件匿名访问 303 跳登录 → 下载带 token 直拼 release download URL；COS 签名 SignatureDoesMatch 对格式极敏感，调通后勿再动签名函数。
- **无删除能力的设计**：IMA 无有效删除端点 → 技能设计成"只增不动"，写操作全部带 folder_id 归属，从源头避免垃圾数据。

## 内容生成质量

- **七维质检**：事实性/合规/结构/价值/风格/原创度/CTA 各占权重，外加四条一票否决（无风险提示/收益承诺/绝对化用语/无源数据）。规则存 `qa-rubric.json`，agent 按 JSON 执行而非自由发挥。
- **persona 越具体越好**：config.json 里定位写"30-55 岁投资者、像资深教练一对一复盘、第二人称"，比"专业作家"产出稳定得多。
- **允许减产**：素材不足时 3→2→1→0 递减并留痕，"不发"比"发空心文"正确。

## 工程细节

- **微信 HTML**：公众号编辑器不吃外部 CSS，必须 md_to_html.py 转内联样式；图片先 compress（sips/cwebp）再传。
- **git 归档**：每篇成稿自动 git commit 到 articles/<日期>[-n]/，等于免费拿到变更历史与回滚。
- **check_drift 防漂移**：技能被 fork/修改多轮后，配置 schema 和台账章节容易漂移，自检脚本按版本锁定校验项。
- **跨平台**：darwin/linux 双平台脚本用命令探测（sips 仅 mac，则 cwebp 兜底），frontmatter 里声明 platforms。

## 移植经验（OpenClaw → WorkBuddy）

- 移植时只改"宿主差异层"（连接器名、spawn 工具名、目录约定），核心流水线/脚本/质检规则零改动——分层结构让移植成本接近零。
